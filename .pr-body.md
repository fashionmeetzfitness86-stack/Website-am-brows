# Production Hardening: Consultation Request System + Secure Admin Login

## Summary

Transforms Ashley M. Brows from a deposit-payment platform into a **luxury consultation request system** with a standalone secure admin login, full booking management dashboard, and automated client email confirmations.

**Build status:** ✅ `TSC: 0 errors` · `vite build ✓ 10.53s`

---

## What's Changed

### 🔐 Secure Admin Login System
- **New:** `/login` route — standalone luxury login page (split-panel design, warm brand palette)
- **New:** `AdminRoute` protected route component — guards `/admin` from unauthenticated access
- Role check on every access: only `super_admin` and `staff` roles allowed — **never defaults to staff**
- Forgot password flow via Supabase `resetPasswordForEmail`
- Show/hide password toggle, loading state, access-denied state
- `handleLogout` now redirects to `/login` (previously `/`)
- Removed embedded login form from `AdminDashboard` (login lives at `/login` only)

### 🗓️ Consultation Request System (No Payments)
- **Removed** entire Stripe deposit/checkout flow from booking
- **New 5-step flow:** Service → Request Date → Request Time → Intake Form → Request Submitted
- Step 5 confirmation: *"Your requested date and time are under review. Ashley will contact you to confirm your official consultation date and time."*
- DB insert status changed from `'Pending Deposit'` → `'New Request'`
- All deposit/payment language replaced with consultation request language
- Removed `@stripe/stripe-js` from `package.json`
- Removed `/booking/success` and `/booking/cancelled` routes

### 📋 Admin Dashboard — Consultation Management
- Table columns: **Requested** date/time vs **Confirmed** date/time (side by side)
- **Manage** button → slide-over detail panel with full booking management UI
- **Approve Requested Time** — one-click to confirm client's request as-is
- **Set Custom Confirmed Time** — date picker + time selector for admin scheduling
- **Inline status dropdown** in detail panel
- **Admin Notes** — editable, saved per booking
- **Send Confirmation Email** and **Send Reschedule Email** buttons
- **Mark Completed** / **Cancel Request** actions
- Status badge stays read-only in table; status updates are done in the panel
- New stat cards: Total Requests / New Requests / Confirmed / New Leads

### ✉️ Confirmation Email Edge Function (`send-confirmation-email`)
- **New** Supabase Edge Function
- Branded HTML email template (warm neutral palette, serif typography)
- Three email variants: `approved`, `modified`, `cancelled`
- Shows confirmed date/time (never the requested date/time)
- Tracks `email_confirmation_sent` + `email_confirmation_sent_at` on booking row
- Uses Resend API (`RESEND_API_KEY` secret)
- Caller must be authenticated `super_admin` or `staff`

### 🛡️ Security Fixes (from previous session)
- **Role default fixed:** `fetchRole` now defaults to `null` — no more implicit staff access
- **Staff removal:** New `remove-staff-user` Edge Function deletes both `user_roles` row AND Supabase Auth account
- **CORS restricted:** `create-checkout-session`, `create-staff-user`, `remove-staff-user` now whitelist only `ashleymbrows.netlify.app` + localhost

### 🔧 Additional Fixes
- Service detail page: `/service-detail` → `/services/:slug` (URL-based, survives refresh)
- Empty testimonials guard (Defining Liner shows "coming soon" placeholder)
- Dead footer buttons fixed (Terms → Policies, Aftercare → Contact)
- `stripe-session-id` column added (separate from `stripe_payment_intent_id`)
- Dead Stripe import removed from `create-staff-user`

## Database Migration Required

Run in Supabase SQL Editor before deploying:

```sql
alter table public.bookings
  add column if not exists confirmed_date                 text,
  add column if not exists confirmed_time                 text,
  add column if not exists email_confirmation_sent        boolean default false,
  add column if not exists email_confirmation_sent_at     timestamp with time zone,
  add column if not exists admin_notes                    text,
  add column if not exists stripe_session_id              text,
  add column if not exists current_area_photo_url         text,
  add column if not exists reference_photo_url            text;

-- Create booking-photos storage bucket
insert into storage.buckets (id, name, public)
values ('booking-photos', 'booking-photos', false)
on conflict (id) do nothing;
```
