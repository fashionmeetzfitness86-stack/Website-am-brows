# Production Launch: Full Platform Polish, Security Hardening & Jotform Booking Integration

## Summary

This PR completes the **production launch readiness pass** for Ashley M. Brows. It covers critical security hardening, routing fixes, a full booking-flow replacement (internal calendar → Jotform), admin dashboard improvements, and all supporting documentation.

---

## ✅ Changes Included

### 🔒 Security Hardening

- **Supabase client (`src/lib/supabase.ts`)** — Removed silent placeholder fallbacks. Now throws a loud startup error if `VITE_SUPABASE_URL` or `VITE_SUPABASE_ANON_KEY` are missing, preventing misconfigured deploys from silently failing.
- **Vite config (`vite.config.ts`)** — Removed `GEMINI_API_KEY` from the `define` block; it was being inlined into the client-side JS bundle and exposed to the browser.
- **Staff removal (`AdminDashboard.tsx`)** — `handleRemoveStaff` now routes through the `remove-staff-user` Edge Function (service_role key) instead of a direct browser-side `supabase.from('user_roles').delete()` call that was blocked by RLS and did not delete the auth.users record.
- **Data loading order (`AdminDashboard.tsx`)** — `fetchData()` now only runs after `fetchRole()` completes, preventing a brief flash of data before the access-denied check fires.

### 🚀 Routing Fixes

- **`/booking/success` and `/booking/cancelled` routes** — Added to `App.tsx`. Without these, Stripe redirect links would 404.
- **Import name fix** — Corrected `BookingResultSuccess/BookingResultFailed` → `BookingSuccess/BookingCancelled` to match the actual named exports in `BookingResultPages.tsx`.

### 🗓️ Booking Flow Replacement (Major)

The internal multi-step booking calendar (400+ lines) has been fully removed and replaced with direct Jotform integration:

| Element | Before | After |
|---|---|---|
| All "Book Now" CTAs | → `/booking` (internal calendar) | Opens Jotform in new tab |
| `/booking` URL | Multi-step internal form | Branded redirect page → Jotform |
| Navbar / hero / services / sticky bar | `onNavigate('booking')` | `openBooking()` → Jotform |
| Homepage bottom CTA text | "Request a Consultation" | "Book Now" |

**Implementation:**
- `JOTFORM_BOOKING_URL` constant at top of `App.tsx` — single source of truth
- `openBooking()` helper — `window.open(url, '_blank', 'noopener,noreferrer')`
- `handleNavigate('booking')` now intercepts all existing `onNavigate('booking')` calls site-wide and calls `openBooking()` — no individual CTA changes required
- New `BookingRedirectPage` component — branded, animated 3-second countdown + "Continue to Booking Form" fallback button for anyone navigating to `/booking` directly

### 🛠️ UX & Polish Fixes

- **Contact form error handling** — Form now shows a visible error message to the user if the Supabase `INSERT` fails (previously succeeded silently on failure).
- **Scroll-to-top button** — Now only appears after scrolling 400px down (was always visible in the corner).
- **StaffJoinPage** — Replaced broken self-registration flow (queried non-existent `staff_invites` table) with a clean redirect page pointing staff to `/login`.
- **Favicon** — Added `<link rel="icon" href="/logo.png">` to `index.html`.

## ⚠️ Environment Variable Requirements

Netlify **Site Settings → Environment Variables** must contain:

| Variable | Purpose |
|---|---|
| `VITE_SUPABASE_URL` | Supabase project URL |
| `VITE_SUPABASE_ANON_KEY` | Supabase anon/public key |

> The app will now **throw a startup error** (white screen + console message) if either is missing.
